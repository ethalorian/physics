# Textbook reading assignments

Teachers open `/admin/readings`, or **Textbook → Assign & review readings**. The review sidebar and class mastery page also link here. This is independent of lessons and the retired assignment system.

## Teacher workflow

1. Select an owned class and textbook chapter. Select sections or enter printed page numbers.
2. Choose a unit and mastery target. Add question numbers in bulk (`1–5, 8`), add the selected sections’ concept checks, or write a prompt. Expand a question to change its prompt or target.
3. Save a private draft or publish to the active class roster. Due dates are optional and late submissions remain accepted.
4. Open the class roster to see not started, in progress, ready to review, needs revision, and rated. Saved drafts show answered counts and last-save time; grading uses submitted snapshots.
5. Rate each distinct assigned target 1/2/3 and save, or return with feedback for another attempt. Missing work never automatically creates a mastery rating.

Each rating writes to the existing `mastery_records` history, credited to the reviewing teacher. One target appearing in several questions still receives one observation. Reading feedback is visible with the student’s assignment. The existing lesson feedback feed and lesson review queue stay lesson-specific; the control room links to reading reviews.

Published question content is fixed. Duplicate a reading to reuse it in another class or change its questions. Archiving retains work and feedback but stops new student answers. A draft cannot become visible through archiving.

## Student workflow

Assigned readings appear on `/home` and `/readings`. The answer workspace opens the existing private chapter reader in place or in another tab. Text answers autosave, can be explicitly saved, and must all be nonempty before submission. Submission locks the attempt. Returned work reopens for revision; previous questions, answers, feedback, and ratings remain in the history. Responses currently use text fields (including calculations); file uploads and drawing tools are not included.

## Integrity and access

- `withAuth` resolves the real NextAuth session. Active course enrollment gates student reads and writes; client user IDs are ignored. Staff reads/writes use owned courses, including verified email aliases, with no admin bypass for another teacher’s class. View-as-teacher mutations are blocked.
- Four new tables have RLS and explicit revokes for public/anon/authenticated. Only the server service role may access them. All three RPCs are security invoker, have fixed search paths, and have public execution revoked.
- Assignment changes, work versions, review transitions, and archives serialize through row locks. Assignment creation also locks its ID. Exact assignment, submission, and review retries are idempotent. Stale drafts cannot overwrite newer work.
- Submitted question/answer snapshots and review rows remain immutable through the app. A review and its canonical mastery records commit atomically. Cross-class/cross-submission review requests fail closed.
- No email, classroom messages, or real student assignments were sent by implementation or tests.
