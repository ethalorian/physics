# Code cleanup and performance refactor — September 7, 2026

## Changes

- Moved QuestionBankProvider and VocabularyProvider from the root layout to the admin layout. All current consumers resolve through admin routes, including the shared question editors. Student and public pages no longer mount these editing contexts.
- Removed three source files with no reachable importers: TeacherMasteryEntry, MathClimb, and the retired unified-assignment types. Marked the historical assignment hub guide as retired. No routes, curriculum artifacts, or database objects were removed.
- Removed unused direct dependencies @auth/supabase-adapter, @supabase/ssr, and date-fns, updating the npm lockfile. Kept @types/three: implicit type resolution makes it necessary even without an explicit import.
- Replaced the question bank's duplicated displayed-list state with memoized filtering. Search and multiple filter selections now apply to the loaded bank; usage updates cannot leave the displayed list stale. Statistics only recompute when questions change.
- Question bank initialization follows App Router navigation and shares concurrent initialization requests.
- Question imports refresh once after all writes, including when an import partially fails. For 100 items, this changes 201 requests into 101 requests (100 writes plus one read). Writes remain sequential to preserve failure behavior.
- Removed unused vocabulary mutation callbacks left behind by a retired write fallback. Memoized the published vocabulary list and context value.
- Added `npm run audit:unused`, a conservative TypeScript import reachability report, and `npm run test:question-bank`.

## Verification

- Production build passed with `NODE_OPTIONS=--max-old-space-size=8192 npm run build`. Includes Next.js type checking and lint; existing warnings remain elsewhere in the repository.
- Changed TypeScript/TSX files passed targeted ESLint with no warnings.
- 27 targeted tests passed: question bank filtering/imports, school-day handling, math student views, and vocabulary learning.
- Reachability audit checked 713 source/script files and reported zero remaining candidates. This is a conservative static check, not proof that every route or exported symbol is used in production. It deliberately treats routes, maintenance scripts, tests and middleware as entry points and never deletes automatically.
- `git diff --check` passed.

## Performance evidence and limits

The provider scope and import request reductions follow directly from the component tree and regression tests. No before/after browser latency or Core Web Vitals measurement was taken, so this change does not claim a percentage improvement in page speed. The initial baseline build ran out of disk space and Node heap; clearing generated Next.js cache and increasing the verification heap allowed the final build to complete. No production deployment or live database writes were performed.

Server pagination for the question bank is unchanged; filtering operates on the API's returned bank. Further scale work should measure bank size and add coordinated server pagination/search if needed. Large component decomposition and database-query tuning should be driven by route profiles and authenticated workflow tests, rather than file length alone.

Lesson-system invariants respected: M-1 (teacher-only mastery ratings), M-4 (shared mastery source), A-2 (no destructive schema changes), and SEI-9 (unchanged prompts/rubrics). Only unreachable legacy UI was removed; active rating and lesson flows were not rewritten.
